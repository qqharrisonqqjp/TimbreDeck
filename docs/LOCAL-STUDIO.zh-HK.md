# 本機工作室：操作及擴充

## 現有流程

- **訓練素材 → 一鍵建立訓練資料集**：選同一位講者的錄音及語言，按需要勾選「先做基礎降噪」。會切段、辨識並匯出包含 `dataset.list`、`wavs/`、`full.wav`、`manifest.json` 的 ZIP。這一步生成訓練資料集，不會直接訓練或覆寫模型。請檢查逐字稿，尤其是口語、專有詞及夾雜語言。
- **去去除雜聲**：除一般降噪和 UVR5 人聲分離之外，可先分離人聲再降噪；同一批錄音可排序後匯出一個 WAV。原錄音不變。
- **錄音匯入**：工作室的合成、情緒、聲音庫、辨識、清理、訓練及兩個擂臺共用匯入接口；接受 WAV、MP3、MP4、M4A、AAC、MOV。WAV 保留原內容；其他格式使用 FFmpeg 取第一條音軌，轉成 32 kHz 單聲道 PCM16。無音軌影片不支援；非 WAV 需要安裝 FFmpeg 及加入 PATH，單檔上載不超過 32 MiB、轉出音軌不超過 180 秒。各引擎的參考音長限制仍生效。匯出仍是 WAV 或訓練 ZIP。
- **切分生成**：啟用後每段 20–2000 字，優先選上限前的句號、問號、感嘆號、分號或換行位置；無適合句末時才用逗號、空格或硬切。每段順序執行；勾選「合併輸出」會寫入同一個 WAV，停頓 0–5000 ms，取消勾選會下載逐段 WAV 的 ZIP。試讀仍只讀第一句。每一段使用同一個參考聲線，失敗或取消不會發佈半成品。
- **兩個擂臺**：ASR 將同一錄音交給已就緒的辨識模型，並排顯示實際模型、逐字稿及包含首次載入的時間；快取會標示。TTS 以同一參考、台詞和錄音複製模式比較已就緒的引擎（Qwen 用 Base），逐一生成及播放/下載。這不是對照所有模式或科學排名。

## 本機 AI

見 [CLI／stdio MCP](AGENT-MCP.md)。用 `--split-at 160 --split-gap-ms 250` 控制分段，`--asr-model faster-whisper-large-v3-turbo` 選已安裝的 ASR。預設選取由工作室依錄音語言決定；使用未安裝的 ID 會報錯，執行期後備會註明實際模型。不要把只可作音色參考的素材用於訓練集。

## 架構檢查：加減新引擎

| 層 | 應改位置 | 驗收 |
|---|---|---|
| 能力與語言 | `studio/engines.go`，聲明 reference、transcript、language、speaker、speed 和模型變體 | 用 `/api/agent/info` 驗能力及就緒狀態，不讀取草稿 |
| 引擎／模型 | `studio/main.go` 的安裝檔檢查、`studio/model_files.go`、`studio/upstream_models.go`；加上鎖定來源及雜湊 | 驗獨立安裝、離線、取消及原資料保留 |
| 合成與證據 | `studio/worker.py` 的 adapter；提供 `execution.json` 裝置證據，若要求 GPU 認證則更新 `studio/execution.go` | 加 API fixture，另用真實模型產 WAV，逐一讀回 |
| 呈現與驗收 | `studio/ui/app.js` 登記人讀名稱／短描述；重測 `tests/acceptance_matrix.py` | 在擂臺、所有支援模式、匯出及 CLI/MCP 驗證 |
| ASR | `studio/asr_models.go` 與 `studio/asr_worker.py`；模型先驗完整性，再加推理 adapter、真實及後備測試 | 避免僅因有權重檔就將未接入的模型顯示為可用 |

目前已有 CLI/MCP 能查詢能力、根據接口選模式，不必模擬點擊，但產品尚非動態插件系統。建議把安裝需求、介面描述與上游來源收斂成同一份版本化 manifest；Python adapter 保持明確列名。切分合成目前每段重開工作程序，隔離好但首段載入較慢；後續可改成一個有生命週期上限的工作程序內逐段生成，保留取消及原子輸出。

## 工作資料

Git 只追蹤程式、文件、測試及已在基線的上游來源檔。模型、錄音、工作室配置、數據集、測試輸出及憑證不應進入 Git。在整併安裝器之前，保持既有引擎連接路徑和 StudioData 原位，避免搬移以致模型找不到。
