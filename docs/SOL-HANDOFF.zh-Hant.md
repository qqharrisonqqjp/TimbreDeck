## 新對話開工指令

> 接手 qqharrisonqqjp/TimbreDeck，使用 PR #1 的 feature/windows-studio-preview 開發線。先核對 HEAD 與基線 4eae57acc4f1784c94266fae0b428fb8300357eb，保留後續提交及現有修改。如果工作區只有舊 main，透過 origin 取得該開發分支。閱讀本手冊及隨附的架構文件。逐項核對已完成的工作，由第一個未完成的工作包開始實作、測試及保存。Windows 硬件或素材暫缺時，記錄阻塞，繼續沒有該依賴的工作。只有實際跑過的組合才標為已驗收。每次交接說明分支、提交、測試結果、產物位置和下一個可執行項目。

## 1　操作設計

| 畫面或情境 | 使用者操作 | 畫面與保存行為 |
|---|---|---|

| 錄音複製 | 選角色或匯入 WAV、預聽、填逐字稿、輸入新台詞 | 原錄音與逐字稿配對。指示、情緒來源、預設說話者按模式出現。空白必填項顯示在對應控制項旁 |
| 聲線設計 | 填聲線描述及台詞，先試讀一句 | 成品保留描述、模型及生成參數。使用者可把滿意的 WAV 存為角色素材，另建相應引擎的聲線資料 |
| 生成途中 | 切另一款引擎、修改下一份草稿或取消 | 全域作業列顯示原引擎、階段及取消鍵；結束後可直達該筆結果。相同工作區同時只擁有一項重型作業 |

| 模型管理 | 選本機引擎、按需下載或從本機清單及分卷匯入 | 顯示變體、版本、下載及展開量、所需新增空間、可用空間。失敗後保留可重用的下載進度並提供重試 |

## 2　介面、資料模型與相容

沿用本機 loopback HTTP、單一工作區鎖、Go 標準庫、內嵌靜態頁及每引擎獨立 Python。優先在現有檔案內引入有測試的入口，有第二個使用者時再共用。引擎包提供依賴、上游原始碼、模型與資產清單；啟動器掌管可執行模式及已知介接程式。

| 契約 | 首批落點及演進方式 |
|---|---|
| 能力目錄 | 在 GET /api/state 的每引擎資料增補 modes 與 variants。每個模式宣告必填及選填欄位、支援的變體、參數範圍；Go 和 UI 共用。既有 ready 仍只表示必要檔案已找到。硬件、模型生成和人工試聽結果獨立記錄，附版本與日期 |
| 合成輸入 | 保留 POST /api/synthesize 既有 engine、mode、text、reference、transcript、instruction、language、refLang、speed、preview。擴充用 variant、voiceId、options。reference 仍指主要音色錄音；第二段情緒錄音置於該模式 options。以引擎、模式、變體驗證欄位、枚舉和相容組合；每次提交建立不可變快照 |
| Worker 邊界 | Go 依能力目錄選固定 adapter，將 ID 解析成工作區檔案後交給 worker。共用輸入為工作描述、暫存輸出及診斷檔位置。引擎例外回傳失敗；子程序成功後檢查 WAV 才提交歷史。大量上游輸出寫入該作業 log，結構化結果另存 UTF-8 JSON |
| 作業診斷 | 診斷綁定 job ID，保存引擎、模型或包版本、模式、實際模型裝置、GPU 名稱、Torch/CUDA 版本、量測方法及可取得的顯示記憶體峰值。嚴格 Windows GPU 驗收檢查作業平台及實際推理路徑；GPU 名稱、CUDA 可用旗標或系統總用量只作輔助。部分組件留在 CPU 時逐項記錄 |
| 角色與歷史 | voices/<sha256>.wav 繼續作素材，建議新增 voices/profiles/<id>.json 儲存名稱、素材引用、逐字稿、語言、衍生模型。outputs/<job-id>/ 維持 speech.wav 及 record.json，擴充來源、變體和裝置。相同素材可被多個角色引用；移除角色前顯示用途，保留歷史播放所需檔案 |
| 相容及搬遷 | 讀入舊 drafts.json、engines.json、record.json 時採舊版預設值；無版本資訊標為未知。內建安裝保存相對路徑，外接路徑失效時可重新定位。版本升級若需改寫使用者資料，先寫新檔、驗讀成功再切換，保留可還原的舊檔 |
| 配置與錯誤 | 保留現有 API 狀態和 error 字串，逐步加入 code 與 field。區別缺素材、模式不合、忙碌、缺模型、GPU 記憶體不足、子程序錯誤、音檔無效、空間不足及封包校驗失敗；有關聯的作業提供 log 位置 |

**提交與恢復**　沿用 running、cancelling、cancelled、failed、done。關閉應停止並回收本作業的子程序樹。啟動時先取得工作區鎖再辨識殘留的暫存產物；只清理確認屬於已中斷作業的暫存目錄。取消與成功同時發生時，以正式輸出提交點決定終態。新作業按 ID 輪詢，較舊的回應不可覆蓋較新的作業狀態。驗收需包含雙擊生成、生成中切換引擎、取消後立即重做及強制關閉後重開。

## 3　逐款引擎的實作規格

各 adapter 的一般流程為本機載入指定模型、轉譯欄位、生成、輸出原生取樣率單聲道 PCM16、回報執行裝置。音色參考、情緒參考、描述、指令與輸出台詞在 UI 和歷史中分欄，只在 adapter 按上游要求組合。開發優先使用 engines/README.md 所鎖定的版本。

| 引擎 | 實作依據與映射 | 該款特有驗收 |
|---|---|---|
| GPT-SoVITS v2Pro | 延用 TTS_Config、TTS.run 及 v2Pro 權重。clone 需 3–10 秒音檔和逐字稿，保留原文語言與輸出語言。GPU 驗收取得實際推理模組的裝置 | 廣東話、參考音長度邊界、離線語言偵測、推理中途報錯不產生成功歷史。後續可選基礎或角色微調模型 |
| CosyVoice 3 | 延用 inference_zero_shot、inference_instruct2、inference_cross_lingual 與目前的提示格式。保留已驗證的 CPU checkpoint 載入方式；Windows GPU 單獨驗收 | 相同錄音比對 clone，再個別測指令及跨語言。完整打包 Matcha-TTS、tokenizer、音色編碼、LLM 及聲學模型；在空快取下生成 |
| VoxCPM2 | src/voxcpm/core.py 與鎖定 README。從本機載入 VoxCPM2。描述放在傳給 generate 的 text 前括號；clone 傳 reference_wav_path；延續模式傳 prompt_wav_path 及精確 prompt_text，可用同一音檔作 reference | 無錄音聲線設計、純錄音複製、同音檔加逐字稿延續三組。由模型讀 sample_rate，與該版本預期 48 kHz 對照。保存可用的 seed 與推理設定 |
| IndexTTS-2 | indextts/infer_v2.py 的 infer。spk_audio_prompt 固定為音色素材；情緒來源枚舉為原音、參考音、文字、向量，分別映射 emo_audio_prompt、use_emo_text/emo_text、emo_vector。強度按適用模式傳 emo_alpha | 兩段錄音可各自播放。向量順序依上游為喜、怒、哀、懼、厭、憂、驚、平靜。切換模式後只送當前欄位。測無選配加速的 Windows 路徑及模型許可聲明 |
| Qwen3-TTS | qwen_tts/inference/qwen3_tts_model.py。Base 用 generate_voice_clone，完整提示附逐字稿，精簡模式用 x_vector_only_mode；CustomVoice 用 generate_custom_voice；VoiceDesign 用 generate_voice_design。語言與預設聲線由載入的型號查詢 | 每個變體可獨立安裝。先以規格選定的 1.7B 驗收，CustomVoice 指令只在型號支援時出現。Chinese 與粵語實測結果分列，三種模型不可錯配呼叫 |

新增模式先做兩個測試：最小合法請求通到預期上游方法、缺必要素材時在提交前得到可理解的錯誤。真實生成、人工聽感及可攜封包按模式及硬件另記。

## 4　封包、更新及離線安裝

1. **組裝。** 每個候選包記下 engine、變體、上游 commit、模型修訂及檔案雜湊、Python/Torch/CUDA 版本、接受測試的驅動/GPU、授權檔、實際大小及可重建步驟。用空的使用者快取測一次，找齊首次推理會用到的輔助權重、字典及 DLL。優先製作 GPT-SoVITS 一般 NVIDIA 版。
2. **建立。** 沿用 tools/make_pack.py，產生不大於 1,800,000,000 bytes 的版本化分卷及 JSON。v1 的 part 命名、順序、大小、每卷及整包 SHA-256、展開量都已有 Go 讀取端。已發佈版本的分卷使用不可變名稱。候選包先在獨立目錄驗證。
3. **安裝。** 下載及離線匯入共用同一條清單檢查、完整性驗證、暫存解壓、內容偵測及版本切換路徑。只接受清單列出的相鄰分卷。估算所需額外空間時扣除可重用的下載；更新保留正在使用的舊版。中斷重試需驗證有關分卷。
4. **啟用與回復。** 區分檔案已裝妥、在本機成功生成、已試聽三個事實。候選版若首次生成失敗，顯示原因及切回上一版的操作。移除舊版須顯示可回收容量及依賴它的角色模型；移除範圍只含由聲台管理的包。
5. **變體演進。** 首兩包保留 packs-v1 的每引擎單一清單。引入 Qwen 多變體前，新增獨立變體目錄/清單識別，與舊版端點並存。先採自足的變體包；只有在實測重複容量值得時才共用已校驗的 runtime，並記錄引用，避免移除一個變體破壞其他變體。
6. **發佈及回滾。** 啟動器沿用現有 Windows 預覽 CI。引擎包由維護者檢視實機結果和授權後，先上傳版本分卷、下載校驗，再更新 packs-v1 對應引擎清單。回滾將清單指向仍在的上一組分卷。記錄實測下載、展開與升級峰值空間，逐步取代規劃估算。

## 5　聲音庫與訓練

角色包含原始錄音及逐字稿版本、語言、參考片段和可選封面。引擎專用 embedding、提示快取與微調 checkpoint 各自記引擎、模型或包修訂及輸入雜湊。模型或逐字稿改變時按來源重新產生快取；原錄音維持可重用。從歷史回放可看到當時使用的角色版本。

GPT-SoVITS 先實作一條完整訓練路徑。每個專案保存階段、資料集索引、配置、鎖定版本、執行紀錄和完成產物，可於 training/<project-id>/ 重開。

| 階段 | 可恢復成果 | 進入下一階段的條件 |
|---|---|---|
| 匯入及切片 | 原始素材 ID、音段起訖、語言、切片版本 | 可逐段播放，每段能追溯原音 |
| 轉錄及校對 | 自動逐字稿、人工修正、採用或剔除、保留作試聽的句子 | 使用者可重開繼續校對，只有已採用片段進入訓練 |
| 特徵準備 | 依固定來源版本的 prepare_datasets 順序產生文字、聲學及語義資料，保存設定雜湊 | 必要輸出齊備且對應本次素材；修改文字或切片只重算受影響成果 |
| 微調 | 核對 v2Pro 上游 webui.py 的 s1/s2 配置與權重配對，透過引擎 Python 執行；保存 checkpoint 與階段結果 | 取消後可繼續已完成階段。只有上游明確支援且配置相容時才從中途 checkpoint 接續 |
| 試聽及登記 | 用保留句與同一參考音生成原版和微調版，保存 WAV、來源與版本 | 通過試聽後登記為角色的可選模型，保留原版供切換。模型檔及授權資料跟隨匯出 |

VoxCPM2 LoRA、Qwen Base 微調及 CosyVoice 訓練列為後續能力，各自先確認固定版本的資料格式、Windows 依賴及最小可重現訓練，再接入既有作業與角色模型流程。

## 7　測試與交付紀錄

開發基線需要 Go 1.23+、Python 3.10+。先確認 go version 顯示 Go 編譯器。以 repo 根目錄執行 go test ./...，編譯 ./studio，再以 python tests/smoke.py 指向本機可執行檔。Windows 用 Start.exe。現有 CI 在 Windows 執行 Go 測試、建置與 smoke；新增驗收程式或測試時同步覆核 CI 路徑篩選。Linux 交叉編譯與 Windows 真實 GPU 執行應各自記錄。

| 驗收層 | 操作 | 結果應可查到 |
|---|---|---|
| 自動回歸 | 沿用 Go 的工作區鎖、可續傳下載、分卷 ZIP、缺件及保留舊版本測試，再補針對此次改動的案例 | 測試命令、平台、提交、通過和失敗項。fixture 驗證介接及流程 |
| Windows 真模型 | 用同一份 3–10 秒單人錄音、實際逐字稿及「今晚八點半喺旺角站等。」依次 clone；再從歷史下載兩個 WAV | 每款保存 job ID、輸入 SHA-256、輸出 SHA-256、取樣率、秒數、峰值、耗時、GPU 證據、模型與驅動版本。輸出需有訊號且與參考音不同 |

**每次收工的紀錄格式**　填寫「分支／提交、完成的工作包、執行命令及結果、真模型與試聽狀態、報告或產物位置、尚缺的外部材料、下一個可執行工作包」。原參考音、模型權重、私有角色錄音及大量輸出存放在使用者選定的位置，交接用檔名、雜湊與位置識別。發佈首包前確認軟件、權重及輔助模型各自的再分發條件，並核對候選包實際含有的授權檔。
