# TimbreDeck 聲台｜架構與開發交接

本設計以 PR #1 的 `4eae57a` 為基線，供 Sol 6.2 分段實作。產品目標是讓 Windows 使用者雙擊 Start.exe、選一款引擎、匯入自己的素材，在本機試聽及匯出 WAV。第一個可交付版本以兩款引擎的 Windows NVIDIA 粵語對照，以及一款可離線使用的引擎包為驗收目標。

## 從哪裏接手

| 項目 | 現有依據 | 開發起點 |
|---|---|---|
| 啟動器與工作室 | PR #1 已有 Go 啟動器、內嵌網頁、五引擎入口、草稿、錄音匯入、歷史及匯出 | 保留現有 HTTP 流程及資料夾，新增能力時一項一項接入 |
| 合成 | GPT-SoVITS 已接錄音複製。CosyVoice 3 已接複製、指令、跨語言。tests/smoke.py 涵蓋四條模擬路徑 | 真實模型對照先用兩者共有的錄音複製模式，其餘模式另記驗收結果 |
| 參考基線 | 上次交接記錄稱兩款真實模型已在 Linux CPU 生成同一句。GPT 為 2.90 秒、32 kHz，Cosy 為 3.24 秒、24 kHz | 從上次存檔取回同一輸入錄音、逐字稿與報告，核對輸入 SHA-256；秒數只供比較 |
| 安裝及派發 | studio/packs.go 已有分卷續傳、整包校驗、暫存解壓及切換。tools/make_pack.py 可產生分卷及清單 | 沿用 packs-v1 協定，先做可驗收的候選包，再發佈 |

## 使用者流程與模組邊界

工作區依序選「引擎 → 模式 → 模型」。台詞和角色素材可帶到下一款引擎，模式、語言、模型選擇及參數按引擎保存。「參考逐字稿」跟隨錄音，與「要讀出的文字」分欄。生成期間切換頁面可繼續編輯；歷史項目保留提交當刻的台詞與參數。

| 責任 | 現有落點 | 設計決定 |
|---|---|---|
| 顯示與輸入 | studio/ui/ | 從 /api/state 讀能力和安裝狀態，按模式顯示必要欄位。下載、取消、試讀及匯出沿用現有 API |
| 能力與設定 | studio/main.go、studio/audio.go | 在 Go 端集中定義引擎 ID、可用模式、模型變體、必填素材、參數與已接通狀態。UI 讀同一份資料，提交時由 Go 再驗證 |
| 作業與檔案 | studio/audio.go、studio/main.go | 延用單一活動作業及工作目錄鎖。提交時固定引擎路徑、模型、參數及素材 ID，切換頁面只影響下一次提交 |
| 模型介接 | studio/worker.py、各引擎自帶 Python | 每項合成啟動一個子程序。Go 經標準輸入傳入工作描述，指定暫存輸出路徑；介接程式處理模型載入、推理和原生取樣率。每款新增引擎有明確的分派，未知 ID 回報錯誤 |
| 安裝與發佈 | studio/packs.go、tools/make_pack.py | 安裝器管下載、容量、校驗及版本切換，模型介接程式讀已選定的安裝。保留手動連接現有引擎的入口 |

一次合成沿用「匯入 WAV → 取得內容雜湊 → POST /api/synthesize → 取得作業 ID → GET /api/job → 讀歷史並下載 WAV」。完成條件是子程序成功、WAV 有效、錄音與記錄一起寫入正式輸出目錄。取消時應等相關程序退出再讓下一個作業使用 GPU。重開後從已完成的輸出還原歷史，暫存輸出不得出現在歷史中。

## 五款引擎的接入契約

| 引擎 | 首批模式與輸入 | 影響架構的差異 |
|---|---|---|
| GPT-SoVITS v2Pro | 台詞、3–10 秒參考音、逐字稿、原文及目標語言 | 保留既有 clone 契約。日後微調得到的角色模型記為衍生版本 |
| CosyVoice 3 | 複製用參考音及逐字稿；指令模式用參考音及講法；跨語言模式沿用已接通介面 | 分別驗證三種模式及提示格式；攜帶鎖定的 Matcha-TTS 及離線輔助資源 |
| VoxCPM2 | 聲線設計用描述及台詞；複製另選參考音；延續模式再加逐字稿 | 必填錄音規則下移到模式。保存描述、模型版本及原生取樣率 |
| IndexTTS-2 | 音色參考音及台詞，情緒來源可選文字、第二段錄音或手動比例 | 音色與情緒採兩個素材 ID。只驗證所選情緒模式的欄位 |
| Qwen3-TTS | Base 用參考音，按模式選逐字稿；CustomVoice 選預設說話者；VoiceDesign 用描述 | 模型變體與模式須相容。包管理及草稿能區別三種變體，按選擇下載 |

能力目錄只公布已實作的操作。將「找到必要檔案」、「這個版本已在指定硬件生成」及「已完成粵語試聽」分開記錄。第三至五款引擎的 UI 開放條件是相應模型已有介接及成功輸出紀錄。訓練後續另設作業類型，保存素材、校對稿、訓練設定和產出的模型版本；首輪先做 GPT-SoVITS。

## 資料相容性與故障處理

- 素材沿用 voices/<sha256>.wav。角色資料引用素材 ID、逐字稿、語言及引擎專用模型。共用錄音一次匯入，替換錄音時重新確認對應逐字稿。
- 草稿沿用 config/drafts.json。增加模型及模式欄位時，舊草稿的預設值應重現現有操作。Go API 現用嚴格 JSON 解碼，先讓後端接受新增欄位，再由內嵌前端送出。將無錄音模式納入驗證測試。
- 歷史沿用 outputs/<job-id>/ 下的 speech.wav 與 record.json。新記錄補充引擎包版本、模型變體、執行裝置及素材 ID；讀舊記錄時缺值顯示「未記錄」。外接引擎版本無法確認時保留其來源類型。
- 失敗時保留作業 ID、階段與 logs/<job-id>.log。安裝中斷可重用已有分卷，候選安裝校驗成功後才更新選用版本。更新失敗時，上一個可用版本仍可啟動。
- 輸入契約與包格式獨立演進。首包沿用清單的 engine、version、expanded、sha256、parts。三款新引擎若需共用執行環境及多個獨立模型包，先定義變體的安裝與選用規則，再開放其下載入口。

## Sol 6.2 實作順序與完成條件

| 次序 | 工作與範圍 | 完成證據 |
|---|---|---|
| 1　補齊 GPU 驗收 | 擴充 tests/acceptance.py 與內嵌 worker。增加可選的 Windows CUDA 驗收，保留現有 CPU 路徑。由實際合成程序回報模型裝置、GPU 型號、Torch/CUDA 版本及可取得的峰值顯示記憶體。按作業 ID 關聯結果 | 原有 Go 測試及四模式 smoke 通過。新增測試覆蓋 CPU 回退與缺少裝置證據。嚴格模式下兩者均不能判為 GPU 通過 |
| 2　Windows 實機對照 | 在有 NVIDIA GPU 的 Windows 使用同一份 3–10 秒錄音、相同逐字稿、台詞「今晚八點半喺旺角站等。」依次經啟動器生成並匯出。保留裝置、驅動、版本、輸入 SHA-256、耗時、輸出 SHA-256、長度和取樣率 | 兩個引擎各自有 GPU 執行證據與有訊號的 WAV。人工逐一試聽「八點半」「旺角站」、句末與音色，在報告分列通過或待修。缺少原錄音時記錄為新基線，兩款仍使用同一輸入 |
| 3　第一個可下載包 | 建議先選 GPT-SoVITS v2Pro 一般 NVIDIA 版，其上游已有 Windows 整合包。固定程式、Python、依賴、模型與輔助檔版本，核對各元件再分發條件及授權聲明，從已通過實機驗收的目錄製作候選包 | 在乾淨 Windows 工作目錄經安裝器裝入候選包，驗證中斷續傳、校驗失敗及容量不足，再測中文含空格路徑、搬移、斷網重開與匯出。記錄下載量、展開及峰值容量；發佈時先上傳分卷，最後更新清單 |
| 4　逐款擴充 | 依第二款引擎的實測封裝 CosyVoice。把前兩款已知能力集中到目錄，再逐款接入 VoxCPM2、IndexTTS-2、Qwen3-TTS。每次只加入當款需要的模式、模型選擇與輸入 | 每款均有對應模式的契約測試、真實生成樣本、離線重開測試。切回前一款仍可讀既有草稿、素材及歷史 |
| 5　角色與訓練 | 增加角色資料及 GPT-SoVITS 訓練流程，串接匯入、切片、校對、微調、對照試聽及儲存角色 | 可中途關閉後恢復已保存的階段，用未參與訓練的同一句台詞比較原版與微調版，並重新選回原版 |

**第一個可獨立審查的改動是步驟 1；完成後按依賴接續後面的工作。** Sol 6.2 從 PR #1 的開發線接手，先讀 studio/worker.py、tests/acceptance.py 和 tests/smoke.py。交付驗收工具、回歸測試及 docs/PREVIEW.md 的執行示例。Windows GPU、完整的兩款 Windows 引擎環境、原參考錄音及逐字稿是步驟 2 的輸入。每次交接分列「工具測試」、「實機生成」、「人工試聽」與「包安裝」，並附對應結果的位置。
